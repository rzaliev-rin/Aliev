# Бот приёма авто в трейд-ин (MAX)

## Что уже готово и проверено

- **`pricing_engine.py`** — расчётный движок, 1-в-1 копирует формулы из вашего
  Excel-файла. Проверен на примере из файла: все 12 итоговых значений
  (категория, план.цена продажи РОП/ДДЦ, валовая прибыль, потолки закупки,
  GM2, статус согласования) совпали с оригиналом до рубля.
- **`bot.py`** — диалоговый сценарий: ссылка на оценку → тип приёма → окрасы →
  тех.состояние → доп.данные → полная раскладка → согласованная цена → статус.
- **`sheets_logger.py`** — запись каждой оценки строкой в Google Таблицу.

## Что нужно доделать перед запуском

### 1. Токен бота MAX
1. Откройте MAX, найдите `@MasterBot`, напишите `/newbot`.
2. Задайте имя и username бота.
3. Получите токен, положите в `.env` как `MAX_BOT_TOKEN`.

### 2. Интеграция с MaxPoster (самое важное!)
Я собрал `maxposter_client.py` как рабочий каркас, но **точный формат
запроса и полей ответа партнёрского API не подтверждён** — документация
(`api.maxposter.ru/partners-api-docs`) открывается только в личном
кабинете партнёра. Чтобы это заработало:

1. Получите API-ключ у вашего менеджера MaxPoster/Autohub.
2. Зайдите в документацию под своей учёткой, найдите метод получения
   оценки по ID (в ссылке `.../appraisals/8550055/view` — `8550055` это ID).
3. Пришлите мне: точный путь эндпоинта, способ авторизации (Bearer-токен /
   заголовок / query-параметр) и пример JSON-ответа.
4. Я подставлю правильные значения в `maxposter_client.py` — это правка на
   10 минут, весь остальной бот уже готов её принять.

**Если по какой-то причине интеграцию не дадут настроить быстро** — бот и
без неё рабочий: менеджер просто пишет «вручную» и вводит ВИН и
Авито-оценку руками, а число ДТП указывает через кнопки «Доп. данные».

### 3. Google Таблица для истории
1. В Google Cloud Console включите Google Sheets API, создайте сервисный
   аккаунт, скачайте JSON-ключ → сохраните как `service_account.json`.
2. Создайте Google Таблицу, откройте доступ на редактирование для email
   из ключа (поле `client_email`).
3. ID таблицы (из адресной строки) укажите в `.env` как `GOOGLE_SHEET_ID`.

### 4. Хостинг
Бот работает через long polling — не нужен ни домен, ни HTTPS, ни белый IP.
Подойдёт любой недорогой VPS с Python 3.10+:

```bash
sudo apt update && sudo apt install python3-pip python3-venv -y
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполните
python bot.py
```

Чтобы бот жил постоянно (а не только пока открыт терминал), заведите
systemd-сервис — могу прислать готовый unit-файл, когда дойдём до этого шага.

## Метрика закупки АСП v2.0 (от 24.09.2026)

`pricing_engine.py` повторяет лист «Метрика оценки» файла «Метрики приёма v2.0
24.09.2026 Экспокар.xlsx»: категория (окрасы + тех. состояние + доп. данные +
пробег в год), ПЦП по автосалону, плановая ВП от ПЦП, потолок к Авито Оценке,
лимит РОП / предел ДДЦ, статусы «Согласовано / Согласование ДДЦ / Согласование
УК / Согласование УК (выше потолка) / Не принимать», GM2.
Проверено тестами на всех 24 примерах листа «Изменения метрики» и на примере
из описания метрики: `python tests/test_pricing_engine.py`.

**ПЦП — по автосалону.** Коэффициенты ПЦП заданы для каждого салона
(раздел «ПЦП автосалона» вкладки «Параметры Метрики v2»): название как в
MaxPoster, % для категорий А/В/С, город и бренд. Салоны Toyota стоят с
коэффициентами Краснодара. В боте салон показывается как «город бренд»
(«Тюмень Toyota») первой строкой расчёта и карточек.

### Что бот подставляет сам (оценщику не нужно вводить)

| Данные | Откуда |
|---|---|
| Автосалон | по названию салона из MaxPoster (номер и «!» в начале не важны); если его нет в таблице — кнопки |
| Год выпуска, пробег | MaxPoster |
| Авито Оценка, VIN, марка/модель, оценщик, салон | MaxPoster |
| Окрасы | MaxPoster (тег «Покрашено» / толщина ЛКП) |
| «Более 3х ДТП» | MaxPoster (`liquidity.accidentsCount` > 3) |
| «Возраст авто до 2х лет» | по году выпуска: если выбрано «Не применимо», бот сам исправит |
| Переподготовка | MaxPoster (`presalePreparationCost`) |
| Цена продажи и цена выкупа (Прогноз ДЦ) | MaxPoster (вкладка «Оценка»), кнопка «Обновить из MaxPoster» |

Вручную остаются: тех. состояние (+ доп. данные, если не определились сами)
и тип приёма, если его код в MaxPoster боту ещё не знаком. Команда администратора `/raw <ссылка|VIN>` показывает все
поля, которые MaxPoster отдаёт по оценке, — по ним можно найти, что ещё
подставлять автоматически.

### Меню и возможности бота

- **Главное меню** (при входе и после каждой оценки): 🆕 Новая оценка, 🧮 Предварительный
  расчёт, 📋 Мои оценки, ❓ Помощь. Команды: /menu, /new, /calc, /my, /help.
- **Цветные статусы**: 🟢 Согласовано · 🟡 ДДЦ · 🟠 УК · 🔴 выше потолка · ⛔ Не принимать.
- **✏️ Исправить** на экране итога тип приёма, окрасы, тех. состояние или доп. данные —
  без новой оценки, статус пересчитывается.
- **Предварительный расчёт** — прикидка без MaxPoster, ничего не отправляется.
- **Уведомления оценщику** в личку о каждом решении: согласовано РОП/ДДЦ/УК, корректировка,
  отказ, приёмка ПАЦ. «Мои оценки» — последние 10 и где сейчас каждая сделка
  (журнал `appraisals_log.json` на сервере).
- **Напоминание**: если сделка ждёт решения дольше 1 часа, бот **один раз** повторно присылает
  карточку с кнопками (в чат салона, УК в личку, в чат ПАЦ) — по одному на каждом этапе.
  Только для сделок, чья карточка реально ушла в чат из этой версии бота, и не старше суток;
  с 9 до 21 по времени сервера. Настройки в `.env`: `REMINDER_AFTER_MINUTES` (0 — выключить),
  `REMINDER_HOURS`.
- **Отчёт** для администраторов: `/report` (7 дней) или `/report 30`, а также кнопка в /admin —
  по салонам: оценки, отправлено, статусы, принято ПАЦ, в работе, корректировки, отказы,
  средняя цена выкупа к Авито.

### Меню администратора (/admin)

- **Заявки на доступ** и **Пользователи** — постранично по 8 человек (у MAX лимит 30 рядов
  кнопок, длинный список раньше не открывался). После «Одобрить», «Отклонить», «Убрать»
  список обновляется на месте; есть «✅ Одобрить всех» с подтверждением.
- **⏳ Оценки в очереди** (или /queue) — все незавершённые заявки: салон, авто, цена, статус,
  этап (салон / УК / ПАЦ / корректировка) и сколько ждёт; самые долгие сверху. Зависшую
  заявку можно закрыть (с подтверждением, оценщику — уведомление).
- **⏸ Остановить / ▶️ Запустить бота** (только владелец, OWNER_USER_ID): во все подключённые
  чаты (салоны и ПАЦ) уходит сообщение «бот отключён» / «бот снова работает»; все
  незавершённые заявки на согласование закрываются (оценщикам — уведомление в личку),
  напоминания по ним больше не приходят. То же делают команды /disable_all и /enable_all.

### Расписание и надёжность

- **Утренняя сводка** (DIGEST_TIME, 09:00): каждому согласующему в личку — что ждёт именно
  его решения (РОП — «Согласовано» и комиссия, ДДЦ — «ДДЦ», УК — статусы УК, ПАЦ — приёмка).
- **Недельный отчёт** (REPORT_WEEKDAY/REPORT_TIME, понедельник 09:00) владельцу и REPORT_USER_IDS.
- **Резервная копия** (BACKUP_TIME, 21:30): доступы, заявки, привязки чатов, журнал — архивом
  владельцу в MAX и в папку `backups/` на сервере (хранится BACKUP_KEEP_DAYS дней). /backup — сейчас.
- **Сообщения владельцу**: «бот запущен», «перезапущен после сбоя», ошибки в обработчиках
  (одинаковые — не чаще раза в 10 минут). Автоперезапуск — служба systemd с `Restart=always`.
- **Повторная оценка VIN**: если по VIN уже есть заявка на согласовании или оценка за
  DUPLICATE_DAYS дней — предупреждение оценщику и в карточке; повторная отправка — с подтверждением.
- **Свежесть Авито-оценки, тип приёма и ПЦП Автохаб из MaxPoster** — по полям из `.env`
  (MAXPOSTER_APPRAISAL_DATE_FIELD, MAXPOSTER_RECEPTION_FIELD/MAP, MAXPOSTER_AUTOHUB_PTSP_FIELD),
  по умолчанию: `inspection.finishedAt`, `acquisitionSource`, `maxposterSaleCost`.
  Тип приёма: `trade_in_new` → Trade-In (в салонах Toyota — Trade-In на ПИ),
  `trade_in_used` → Trade-Up, коды со словом buy/выкуп → Выкуп с улицы, commission → Комиссия.
- **Комиссия** — согласование по метрике не требуется: карточка уходит в чат салона на
  подтверждение РОП (могут также ДДЦ/УК), затем в ПАЦ. Лимиты метрики показываются справочно.
- **Статусы УК** (выше предела ДДЦ, выше потолка, «Не принимать») — без согласования ДДЦ:
  карточка сразу уходит УК (лично и в чат салона), после решения УК — в ПАЦ.

### Отчёт /report

Всего оценок и сколько отправлено; категории А/В/С — количество и доли; уровни согласования
(🟢 🟡 🟠 🔴 ⛔) — количество и доли; ПЦП к Авито-оценке по категориям (по метрике и по
прогнозу ДЦ); цена выкупа к Авито; итоги (ПАЦ, в работе, корректировки, отказы, закрытые);
ниже — коротко по каждому салону.

### Настройка Google Таблицы для v2

1. Создайте вкладку **«Параметры Метрики v2»** и вставьте в неё содержимое
   `params_table_v2.csv` (первая строка — заголовки). Старая вкладка
   «Параметры Метрики» (нормы v1) больше не читается. Пока новой вкладки нет,
   бот считает по нормам v2, зашитым в `pricing_config.py`.
2. **Новый салон**: добавьте строку в раздел «ПЦП автосалона» вкладки
   «Параметры Метрики v2» — Параметр = название точно как в MaxPoster,
   Значение1–3 = % ПЦП для категорий А/В/С, Значение4 = город, Значение5 =
   бренд. Бот подхватит строку в течение 15 минут, без перезапуска. Чтобы
   карточки согласования шли в чат салона, добавьте салон и во вкладку
   «Иерархия согласования» и выполните /register_salon в его чате.
3. История оценок по метрике v2 пишется в отдельную вкладку **«История
   оценок v2»** (переменная `GOOGLE_SHEET_TAB_V2`). Старая «История оценок»
   остаётся архивом v1 и больше не пополняется.

Вкладки «Параметры Метрики v2» (с 8 салонами) и «История оценок v2» в
рабочей таблице уже созданы.

## Как поменять коэффициенты/пороги в будущем

Все нормы (баллы, пробег в год, ПЦП по автосалонам, доходность, потолок, GM2)
меняются во вкладке «Параметры Метрики v2» — без правки кода и перезапуска
(бот перечитывает её раз в 15 минут). Формат вкладки описан в начале
`pricing_config.py`. Значения в коде — запасной вариант на случай, если
таблица недоступна.
